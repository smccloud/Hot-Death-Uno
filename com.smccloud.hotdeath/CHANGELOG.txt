================================================================================
Everything below this line was released in 2026. The gap is fourteen years:
nothing was published between 1.0.5 in December 2012 and 1.1.0 in September
2026, during which the toolchain moved from Ant to a modern Gradle and the app
from Java to Kotlin.

Note that 1.0.6 through 1.0.12 were never published here either. They exist only
in the upstream project's own history.
================================================================================

Version 1.1.0                2026-09-30

 - first release from the modernized toolchain: AGP 8.11.1, Gradle 9.5.0, JDK 17,
   compileSdk 36, minSdk 34, targetSdk 36

 - retargeted to Android 16. Edge-to-edge is now mandatory at targetSdk 35+, so
   each activity installs a WindowInsets listener and pads itself by the
   system-bar and display-cutout insets. Uses the platform WindowInsets API
   rather than androidx.core, which keeps the app at zero third-party runtime
   dependencies

 - rotation no longer recreates the activity: configChanges is declared on all
   three activities, which also stops an in-progress game being lost on rotate

 - 114 JVM and Robolectric unit tests added across the pure-logic classes

Version 1.1.143              2026-09-30

 - 140 unit tests now, from 114

 - NOTE: this version's patch number was documented as "the count of passing
   tests, 116 unit plus 27 instrumented". That was never accurate. The
   instrumented suite has only ever held 9 tests (PenaltyStackTest's 6 plus
   MainLaunchTest's 3), so the real total was 125, not 143. The number was
   carried forward by adding rather than recomputing. See version 1.4.6.

Version 1.2.0                2026-09-30

Version 1.4.6                2026-10-01

 - VERSIONING FIXED. The scheme documented in build.gradle claimed the patch
   number was the count of passing tests. It had not been since 1.4.0, and it
   had never matched the real counts either (see the 1.1.143 note above). Now:
   plain MAJOR.MINOR.PATCH, with the patch a release counter within the minor
   line

 - versionCode is derived from versionName in the build script rather than typed
   alongside it, so the two cannot disagree. The encoding is unchanged --
   major*1000000 + minor*1000 + patch -- so no published versionCode moves

 - added a verifyVersionCode task that fails unless the declared versionCode is
   strictly greater than the highest published v* tag. Until now nothing checked
   this at all: the rule was stated in a comment and enforced by hand. The
   Jenkinsfile runs it before the release build, and its Checkout stage now
   fails if the tags were not fetched, since the task cannot compare anything
   without them

 - no application code changed. The test count is unchanged at 140 unit plus 9
   instrumented
     

Version 1.4.7                unreleased

 - the test suite is Kotlin, which finishes the 1.4.5 migration: there is no
   Java source left anywhere in the repository. The 11 test files moved from
   src/test/java and src/androidTest/java to the kotlin/ directories beside
   them, which needed no build change -- AGP and the Kotlin plugin register
   src/<sourceSet>/kotlin themselves

 - the conversion was not a transliteration, and it turned up one real bug.
   GameRoundLoopTest asserted that every card in the deck was in a hand, a
   draw pile or the discard pile. Written the Java way it reads as

       val accounted = inHands
               + game.getDrawPile()!!.getNumCards()
               + game.getDiscardPile()!!.getNumCards()

   but Kotlin reads a line-leading + as unary plus and ends the declaration
   there: accounted was inHands alone, so the assertion compared one pile
   against the whole deck. It compiled without a warning. Java has no such
   reading, so the same text meant something else in the file it came from.
   The counts are now named and summed on one line

 - where nullability actually bit was not where the issue predicted. Hand(null)
   compiled unchanged everywhere, as expected. CardPile.getCard,
   Hand.getCard, Hand.getLowestCard and CardDeck.getCard are all nullable, so
   the reads inside loops needed !!, and each one now carries a comment saying
   why the read is safe instead of a bare !!. JsonRoundTripTest documents that
   the seat-index round trip is what makes Hand(null) legal, so tightening Hand
   breaks one assertion rather than forty call sites

- the reflection helpers in HandPlayabilityTest and GameRoundLoopTest now say
   out loud that f.set bypasses Kotlin's intrinsic null checks, which is why
   the AssertionError on a renamed field is the only guard there is

 - BUG FIX. The green 3 infection was charged again in every round after the
   one it was picked up in, and the running total grew by the whole accumulated
   penalty each time. A player who picked up a green 3 in round 1 paid 10 again
   in round 2 with no green 3 in sight, 20 again in round 3, and so on for the
   rest of the game

   Hand.calculateValue accumulating 10 per green 3 on a final score is correct
   and is untouched -- two cards, two infections. The compounding was one level
   up: Game.calculateScore adds the player's whole getVirusPenalty() to their
   round total, and nothing cleared that field between rounds. Only
   Player.resetGame() did, and that runs once per game. resetRound() now clears
   it, which is the round boundary and where the field's other round-scoped
   state already resets

   The winner was exempt from the charge, which was the one hint this was not
   meant to compound. That exemption is left as it is -- it is a separate rule

 - GameRoundLoopTest now pins the charge against the hand it should have come
   from: after a round, lastVirusPenalty must be exactly 10 per green 3 in that
   hand, for everyone but the winner and anyone holding all four bastard cards.
   The check runs on the random deal, which is not enough on its own -- on a
   deal with no green 3 in it the bug never fires -- so two further tests set
   the field by hand and drive two rounds around it

 - test count is 142 unit plus 9 instrumented. The two Hand-level tests that
   cover the accumulation, theVirusPenaltyAccumulates and
   theAidsCardInfectsOnlyOnTheFinalScore, both pass and both stay passing: the
   bug was never on that side
